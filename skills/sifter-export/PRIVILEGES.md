# Privileges to request for sifter-export

Proposed privileges, not verified grants on this OEM device. The portal
privilege labels alone do not expose host/scanner directories: the actual
source mounts or supported producer/API integration must be specified.

| Privilege | Why |
| --- | --- |
| File system volumes | Read only explicitly granted/mounted data; scanner/host paths are not yet identified or approved |
| Removable media | Write exports directly to a USB stick in the USB-A host port (alternative to network POST) |

Deliberately NOT requested (keep the approval case simple):
- GPIO, audio, camera (not needed for export)
- Elevated OS capabilities / network raw sockets

If the portal requires justification text per privilege:
- File system: "Export the device owner's scan results and diagnostic data
  to their own storage, per the platform's data-ownership goals."
- Removable media: "Allow direct export to a USB drive attached to the
  device's host port."

Fallback if file-system privilege is denied: run the export agent with
only removable-media privilege and have the workflow's earlier stage
(or IoT messages) deliver the data.

## Documented Optra Edge privilege mechanics (`docs.optra.com`, 2026-11-23)

Source: `https://docs.optra.com/skills/privileges/` and `https://docs.optra.com/skills/add-skill/` `[O]`.

- **Docker Image vs. Docker Compose restriction `[O]`:** `Docker Compose` skills (uploaded as `.tgz` via the portal) support **only** `Env` and `Web UI`. All storage, hardware, and networking privileges (`Volumes`, `Removable Media`, `Port Bindings`, `Host Networking`, `NET_ADMIN`) apply **only to `Docker Image` skills** pulled from a registry (Docker Hub, Azure ACR, or private registry; AWS ECR not supported). Any real deployment of `sifter-export` that needs `Volumes` or `Removable Media` must therefore be packaged as a **Docker Image** skill rather than a Compose archive `[I]`.
- **Exact Docker `HostConfig` options generated by the Optra agent `[O]`:**
  - **Removable Media:** `HostConfig.Binds`: `/run/removable_media:/media:shared` (shared bind propagation; correlates with the `Auto Config & Mount extended storage` boot unit `[I]`).
  - **Volumes:** `HostConfig.Mounts` (`type: volume`, alphanumeric `Source`, absolute container `Target`, optional `VolumeOptions.DriverConfig.Options.size`). Named volumes remain private to the skill unless another container shares the same volume name `[I]`.
  - **Tmpfs / SHM:** `HostConfig.Mounts` (`type: tmpfs`, optional `TmpfsOptions.SizeBytes`); `HostConfig.ShmSize`.
  - **Network Endpoint Alias:** `NetworkingConfig.EndpointsConfig['azure-iot-edge'].Aliases` (containers share the `azure-iot-edge` Docker network).
  - **Web UI:** `HostConfig.PortBindings` mapping `{exposedPort}/tcp` (optionally `HostIp: 127.0.0.1`), proxied through the Optra Portal.
  - **Port Bindings:** External host port bindings explicitly **forbid host ports `22, 53, 80, 443, and 8080`**.
  - **Host Networking / `NET_ADMIN`:** `HostConfig.NetworkMode: host` and `HostConfig.CapAdd: ["NET_ADMIN"]` require org-level feature flags enabled by Optra support.
- **Inputs / Outputs `[O]`:** Skill inputs are delivered through Azure IoT module twin desired settings (read via the Azure IoT device SDK); outputs are emitted as JSON payloads over Azure IoT messages.
